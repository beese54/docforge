docforge · how it works

An AI agent documents your code. A person decides what leaves.

1 · IN

Your code

A copy goes into the sandbox. The agent never touches the original.

Approved docs come back here in step 4, on a new branch.

the only door out

Anthropic's AI service

The access key is added at the door. The agent never sees it.

2 · AUTONOMY INSIDE

Locked sandbox (NVIDIA OpenShell)

The AI agent works on its own

Reads the code, works out how it fits together, and writes the documentation.

It can

  • ✓Read the copy of your code
  • ✓Draft documentation (text only)
  • ✓Talk to Anthropic's AI, through the one door

It cannot

  • ✕Reach any other website. Attempts are blocked and logged
  • ✕See the access key
  • ✕Change code or system files
  • ✕Spend past a hard budget cap
Proven by attack · 8 of 8 security checks pass

Example: a test script makes the sandbox try to reach another website (example.com). The connection is refused, and the attempt is written to the log.

3 · OUT

A proposal

Nothing has changed yet. Only suggestions come out:

the suggested docs
a report of what it found, including gaps
4 · APPROVAL AT THE BORDER

Outside the sandbox, you decide each step

  1. 1Review every lineOn screen only. Nothing changes yet.
  2. 2Apply to a new branchIn your repo. Docs files only; the main version is untouched.
  3. 3PushSends that branch to GitHub.
  4. 4Open a pull requestAsks to merge the docs into main.

Before each step, the screen shows exactly what will change or leave the machine.

Nothing merges on its own. You merge on GitHub.
